# STM32 学习笔记编辑规范

本 Skill 适用于修改 `c:\Users\tanxin\Desktop\学习图片\STM32\stm32.md` 的所有场景。每次收到修改文档的请求时，**必须严格遵守以下四步流程**，不得跳过任何一步。

---

## 第一步：读取当前文件

使用 `Read` 工具读取 `stm32.md` 的完整内容，确认：

- 文档当前的标题层级结构（# / ## / ###）
- 已有的图片引用路径格式（`./日期文件夹/图片名.扩展名`）
- 已有的编号体系（章节号是否连续、日期分节是否完整）
- 需要修改的位置的上下文内容

**禁止** 在没有读取文件的情况下直接执行 Edit 或 Write 操作。

---

## 第二步：查找本地参考资料

在执行扩写或新增知识点之前，先在当前工作目录下搜索用户提供的参考资料：

- 使用 `Glob` 搜索 `.pdf`、`.doc`、`.docx`、`.txt`、`.md` 等文档
- 使用 `Glob` 搜索用户提到的课件、讲义、笔记截图等
- 使用 `LS` 查看各日期子文件夹中是否有配套图片
- 使用 `SearchCodebase` 全文搜索关键词

如果本地找到了参考资料，**优先参考本地资料**来编写内容。

---

## 第三步：联网搜索补充资料

**如果本地没有找到足够的参考资料**，必须使用 `WebSearch` 工具联网搜索相关内容，搜索时注意：

- 使用精确的 STM32 专业术语作为关键词（中文+英文缩写），例如：`STM32 I2C 标准模式 快速模式`、`STM32 EXTI 外部中断 下降沿触发`
- 优先搜索权威来源：ST 官方参考手册（Reference Manual）、STM32 中文参考手册、正点原子/江协科技/野火的教程、CSDN/博客园上质量高的技术博客
- 搜索内容必须是真实存在的技术知识点，**确保浏览器可以搜到**
- 搜索数量建议 `num: 5`，取最相关的 3-5 条结果进行交叉验证

### 搜索质量验证清单

在使用搜索结果编写内容前，确认：

- [ ] 该知识点在 STM32 官方手册中有明确记载
- [ ] 至少有 2 个不同来源的资料说法一致
- [ ] 涉及寄存器配置时，寄存器名称和位域定义与参考手册匹配
- [ ] 涉及库函数时，函数名、参数名与 STM32 标准外设库/LL 库一致

## 第四步：执行修改

基于前三步收集的信息进行编辑，注意以下规范：

### 文档结构规范

- 一级标题 `#` 用于文档主标题和日期分节（`# STM32 学习笔记`、`# 10月27日`）
- 二级标题 `##` 用于大章节，编号格式为 `## 章节号. 章节名`（如 `## 11. I2C 通信`）
- 三级标题 `###` 用于小节，编号格式为 `### 章节号.小节号 小节名`（如 `### 11.1 I2C 协议概述`）
- 新增章节号必须接续已有编号，不得重复或跳过

### 图片引用规范

- 图片放在对应日期的子文件夹下，路径格式：`./日期文件夹/图片名.扩展名`
- 图片插入在对应的小节标题之后、说明文字之前
- 图片下方用 `> ` 引用块说明图中的关键名词和核心概念

### 内容撰写规范

- 语言风格与已有内容保持一致：通俗易懂、有条理、善用类比（如人体类比）
- 概念解释要深层剥析，不只说"是什么"，还要说"为什么"和"怎么用"
- 涉及参数/模式对比时，优先使用 Markdown 表格展示
- **分类必须画表**：当一个知识点有多种分类（如 GPIO 的 8 种工作模式、定时器的 3 大类型、I2C 的 2 种速率模式等），必须用表格一次性呈现所有分类，让读者一张表看懂全部，而不是分散在多个段落里逐一描述
- 涉及库函数时，说明函数名、参数含义、返回值和典型调用方式
- 涉及寄存器时，说明寄存器名称、关键位的含义和配置值
- **绝对禁止凭空捏造**：任何无法通过本地资料或联网搜索验证的内容都不能写入

### 重点标记规范

在修改或编写文档时，**必须识别并标记重要的核心知识点**。`>重点：` 是知识点的标题标签，**只写简洁的一句话点明主题**，详细解释放在标记下方的正常段落中。

**格式**：
```
>重点：一句话点明这是什么知识点（简洁、不展开）
```
（下面紧跟正常段落，写详细的解释和说明）

**规则**：
- `>重点：` 是**标签**，不是正文，字数尽量控制在一行以内
- 重点标签放在标题下方，标签下面是详细正文
- 不要在 `>重点：` 里展开解释，解释全部放在标签下方的段落里
- **用户自己写的 `>重点:` 绝对不能删除**，只能保留或在重复时调整标题文字
- 如果扩写时新增的 `>重点：` 和用户已有的 `>重点:` 表达的是同一个知识点，**保留用户的原始标签**，只在其标题不够清晰时做微调（如补充关键词），不新增重复标签

**正确示例**：
```
### 18.4 逻辑「线与」——I2C 的精髓

>重点：开漏输出实现线与逻辑

总线上所有设备的 SDA 引脚都是开漏输出——只有拉低和高阻态两种状态...
（详细解释放在这里）
```

**错误示例**：
```
>重点：总线上所有设备的 SDA 引脚都是开漏输出，只有拉低和高阻态两种状态，当所有设备释放时上拉电阻拉高，任意一个拉低总线就为低，形成了逻辑与关系
```
（标签里堆了一大段解释，太长）

**必须标记的知识点**：
  - GPIO 八种工作模式（推挽/开漏区别）
  - 中断/NVIC 优先级分组
  - 定时器与 PWM
  - I2C 通信协议（起始/停止条件、开漏原因、ACK 机制、线与逻辑）
  - SPI 通信协议
  - UART/串口通信（帧格式、标志位 TxE/TC/RxNE）
  - DMA 工作原理
  - ADC 模数转换
  - 时钟系统（HSE/LSE/PLL）
  - 看门狗
  - 启动模式
  - 寄存器操作（BSRR vs ODR）
  - 串并转换与移位寄存器
  - 引脚重映射
  - 中断 vs 轮询

## 第五步：修改完成后提交到 Git 仓库

每次完成 `stm32.md` 的修改后，**必须自动执行一次 Git 提交和推送**，将变更同步到远程仓库。

### 操作步骤

在 `c:\Users\tanxin\Desktop\学习图片\STM32` 目录下依次执行：

1. **添加所有变更**：`git add stm32.md`（只提交笔记文件，不提交无关文件）
2. **生成提交信息**：根据本次修改内容概括一条中文 commit message，格式为 `更新笔记: 简短描述本次改动`
3. **提交**：`git commit -m "更新笔记: 描述"`
4. **推送到远程**：`git push`

### 提交信息示例

| 本次改动 | commit message |
| --- | --- |
| 插入 10.29 图片并扩写 I2C 读数据 | `更新笔记: 10.29 I2C读数据+OLED原理` |
| 插入 11.1~11.3 图片并扩写 SPI+中断 | `更新笔记: 11.1-11.3 SPI通信+中断优先级` |
| 精简重点标记、补充 I2C 标志位表格 | `更新笔记: 精简重点标签+SPI概述` |
| 修改文档标题层级、重新编号 | `更新笔记: 调整标题层级与编号` |

### 注意事项

- 如果 `stm32.md` 没有改动（本次对话未涉及），则跳过提交步骤
- 如果有新增图片文件夹，一起 `git add` 提交
- 如果 git push 失败（如网络问题），提示用户手动推送，不要反复重试
